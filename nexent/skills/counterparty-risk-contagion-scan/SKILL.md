# 关联方风险传导扫描

找出**不是目标企业自己身上、但会传导到它身上**的风险。

目标企业自身经营正常、社保按时缴纳、没有涉诉记录，却仍然可能是高风险主体——
因为它的股东、实际控制人、关联公司已经出险了。这类风险不出现在目标企业的
任何一条直接记录里，只能沿着关联关系走一跳才能看见。

这个技能就是走这一跳。

## 可用方法

`kg_path_query`（主）、`gov_social_security`、`gov_judicial_scan`、`fin_financial_parser`（取目标企业自身记录）

## 方法参数

### kg_path_query

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| start | string | 是 | - | 起点节点 ID，取自核验技能返回的 `subject.node` |
| constraint | string | 是 | `关联方风险传导扫描` | 路径约束名 |
| max_hops | int | 否 | 约束内置 | 最大跳数；触发 `truncated` 时用来收紧重试 |

本技能固定使用 `constraint="关联方风险传导扫描"`，它把搜索限定在一条固定形状的链上：

```
企业 ──关联关系──> 关联主体 ──政务记录──> 风险指标
```

三跳以内。形状固定是有意的：风险传导只有这一种走得通的形式，
放开形状会搜出大量与传导无关的路径，把真正的信号淹掉。

## 使用方式

<code>
node = gov_business_lookup(subject="甲科技有限公司")["subject"]["node"]

# 目标企业自身的记录（直接采集，比路径搜索更快）
own = {
    "social":   gov_social_security("甲科技有限公司"),
    "judicial": gov_judicial_scan("甲科技有限公司"),
    "finance":  fin_financial_parser("甲科技有限公司"),
}

# 关联方传导（跨域多跳）
scan = kg_path_query(start=node, constraint="关联方风险传导扫描")
if not scan["paths"] and not scan["rejected_paths"]:
    integrity_note = "未采集到该主体的关联关系数据"   # 见"错误处理"第 2 行
</code>

## 返回值

```
{
  "ok": true,
  "paths": [ { "node_ids": [...], "edges": [...], "confidence": {...} } ],
  "rejected_paths": [ { ..., "reject_reason": "..." } ],
  "truncated": false,
  "truncated_reason": ""
}
```

**`rejected_paths` 必须读，不能只看 `paths`。** 被拒绝的链是审计的依据：
当业务方质疑"我明明看到它有个关联公司出事了，你为什么说没风险"时，
答案就在被拒路径的 `reject_reason` 里——通常是置信度不够，
而不是那条链不存在。这两件事的处置方式完全不同。

每条采纳的路径都要**按跳展开**呈现，不要只给一个风险分数：

```
甲科技有限公司
  └─ 持股 60% ─> 乙贸易有限公司          [来源：企业关联关系.csv]
       └─ 行政处罚 ─> 被处罚 3 次，罚款 12.5 万元
            └─ 触发 ─> 风险指标「关联方行政处罚」
```

每一跳都要带上它的来源。用户要能顺着这条链一路点回到原始文件。

## 证据口径与阈值

采纳阈值 **0.5**，比真实性核验（0.8）低。

这个差异是有意的。真实性核验要的是"确认事实"，所以要高阈值、宁缺毋滥；
风险传导要的是"发现问题"，漏报的代价高于误报——一家企业被多扫出几条
关联风险，人工复核一次就澄清了；而漏掉一条传导路径，
可能意味着几百万的坏账。

但阈值低**不等于可以不看置信度**。传导链的置信度由最弱那一环压制
（瓶颈保护），所以要看的是：**这条链上最低的那一跳是哪一跳、有多低。**
一条 0.5 的链和一条 0.85 的链在业务上含义不同，前者需要复核，后者可以直接采信。

## 错误处理

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| `paths` 为空但 `rejected_paths` 非空 | 找到了传导链，但都没过 0.5 阈值 | **有可疑信号但证据不足**，转人工复核，不要当作无风险 |
| `paths` 与 `rejected_paths` 均为空 | 确实没有关联方风险，**或关联关系数据缺失** | 先用 `graph_stats` 确认图中存在 `企业关联关系` 类型的边。缺失时结论写"未采集到该主体的关联关系数据"，**不要写"该主体无关联方风险"** |
| 返回 `truncated=true` | 展开预算耗尽（集团客户等关联关系密集的主体易触发） | 收紧 `max_hops` 重试，先把两跳以内的高置信传导捞干净。不要直接采信截断结果——截断意味着还有没走完的路径，其中可能有更严重的风险 |
| 传导链置信度突然很低 | 某跳只有 LLM 派生证据，或条款措辞模糊 | 这是设计行为。派生边和 LLM 边的置信度本就低于直接证据，并通过瓶颈保护压低整条链。如实呈现这个不确定性，比给一个看似精确的假分数更有价值 |
| 关联主体名称对应多个实体 | 该关联记录缺少强标识符 | 图加载阶段已用统一社会信用代码做过实体归并，正常不会出现。若仍遇到，标注为"关联主体待确认"，其传导路径降级使用 |

## 输出契约

1. **传导路径列表**：每条按跳展开，逐跳附来源
2. **被拒路径及理由**：审阅者判断"是真没风险还是没查到"的依据
3. **数据完整性声明**：本次扫描覆盖了哪些数据源，哪些缺失
4. **瓶颈提示**：每条链最弱的一跳及其置信度

## 与下游的契约

- 前置：`enterprise-authenticity-check` 结论为"通过"
- 输出：把命中的风险指标节点传给 `credit-decision-chain`，
  由后者判定这些风险是否触碰了监管阈值

**本技能只识别风险信号，不判定是否违规。** "关联方被行政处罚 3 次"
是风险信号；"这件事是否突破了监管容忍度"是阈值判定要回答的问题。
两者分开，是因为同一个风险信号在不同业务规则下的处置可以完全不同——
是否触发取决于适用的监管条款，而那是下游技能的事。
