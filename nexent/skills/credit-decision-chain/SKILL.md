# 授信决策链生成

把散落的风险信号，加工成一个**能追溯到监管条款原文的**授信结论。

上游技能回答的是"有没有风险"；本技能回答的是"这个风险在本案适用的监管
口径下，算不算越界"。这两件事之间隔着一次跨层推理——
从实体图谱里的事实，跨到规则图谱里的条款和阈值。

结论必须是可追溯的：每一个判定都要能回指到具体条款编号和原文。
不能追溯到条款的结论，在授信场景里等于没有结论。

## 可用方法

`risk_decision`（主）、`evidence_bundle`、`kg_path_query`、`ontology_status`

## 方法参数

### risk_decision

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| subject | string | 是 | - | 企业名称或统一社会信用代码 |
| persist | bool | 否 | `true` | 是否把决策写入运行时图。自检或试算时传 `false` |

### evidence_bundle

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| decision_id | string | 二选一 | - | 形如 `DEC-XXXXXXXXXXXX` |
| subject | string | 二选一 | - | 取该主体最近一次决策 |

## 使用方式

<code>
# 前置：确认图谱已加载（规则图为空时跨层推理必然失败）
stats = graph_stats()
if stats["graph"]["by_layer"].get("规则图", {}).get("nodes", 0) == 0:
    raise RuntimeError("规则库未就绪，不应给出授信结论")

decision = risk_decision(subject="甲科技有限公司")

# 提取结论与依据
verdict   = decision["verdict"]         # 建议通过 / 审慎核定 / 不予受理 / 证据不足
conf      = decision["confidence"]
judge     = decision["judgements"]       # 触发的阈值判定
dec_id    = decision["provenance"]["decision_id"]

# 取回可追溯依据
bundle = evidence_bundle(decision_id=dec_id)
</code>

内部按三个阶段串联执行，任一阶段失败都会影响结论：

```
阶段1  企业真实性核验（闸门，未过则立即终止，不产生后续步骤）
   ↓
阶段2  关联方风险传导扫描（采集风险指标）
   ↓
阶段3  授信决策链生成（风险指标 → 风险维度 → 监管条款 → 判定阈值）
```

## 返回值与结论解读

四种结论，对应四种完全不同的业务动作：

| 结论 | 含义 | 业务动作 |
|---|---|---|
| `建议通过` | 未触碰任何监管阈值 | 可进入正常审批流程 |
| `审慎核定` | 触碰阈值，需人工复核 | 转人工，附带触发的条款 |
| `不予受理` | 真实性闸门未通过 | 终止，不进入审批 |
| `证据不足` | 数据不完整，无法判定 | 补采数据后重跑 |

**`证据不足` 不是失败。** 它是系统在数据不完整时拒绝编造结论的正确行为。
把 `证据不足` 报告成"未发现风险"是信贷场景里最危险的错误——
它把"不知道"伪装成了"没问题"。

每条判定的三个必备要素：

```
判定：连续异常月数上限 = 3，观测值 3（同维度风险指标出现 3 次），触发
依据：3 ≥ 3
条款：银保监发〔2024〕12号-§4.1
```

只给"触发"两个字，业务方无法复核。

## 置信度解读

决策置信度由各阶段代表链的置信度**几何平均**合成：

```
决策置信度 = (真实性 × 传导 × 阈值判定) ^ (1/3)
```

用几何平均而非加权平均，是因为三个阶段是**串联**关系：
真实性、传导、阈值判定缺一不可，任何一环弱都会拖垮整体。
几何平均天然被最弱环节压制，因此**看置信度就是看最弱的那个阶段**。

反面做法：把所有采纳路径当作独立证据累加。同一个结论的十几条走法
其实是同一份证据的不同路线，累加会把置信度顶到 0.99 以上，
让"一份社保记录加一条监管条款"看起来铁证如山。

## 错误处理

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| 触发的判定为空，结论为 `建议通过`，但阶段 3 的采纳路径为 0 | **不是没风险，而是没找到适用条款** | 调 `ontology_status` 检查本体覆盖度。UNK 储备池堆积大量未演化概念说明当前本体未覆盖该领域的监管表达方式，此时"未触碰阈值"不可靠，应标注"规则覆盖不足" |
| 结论为 `证据不足` | 某阶段数据缺失 | 调 `evidence_bundle` 定位缺失阶段，列出补件清单交回业务方。**不要重试**——重试不会让缺失的数据出现 |
| 决策置信度偏低（< 0.5） | 某跳只有 LLM 派生证据，或条款措辞模糊 | 调 `evidence_bundle` 看各阶段置信度找出瓶颈阶段，如实呈现瓶颈，不要给笼统的"置信度低" |
| `drift` 列表非空 | 决策作出后图上数据已变化 | `drift` 非空**不代表决策有错**，表示该结论需在今日数据下重新评估。列出 drift 项让业务方决定是否重跑。不要静默忽略，也不要仅因 drift 就推翻原决策 |
| 返回 `truncated=true` | 展开预算耗尽 | 收紧约束重试，或在结论中明确标注覆盖不完整。截断结果不能作为最终授信依据 |
| 同一阈值只附了一条链 | 去重结果，非漏报 | 同一个阈值可能被同维度下多个指标各自走到（"连续三个月异常"天然有三条入口）。系统按阈值节点去重，只保留置信度最高的代表链——它们是同一条判定依据的三种走法，不是三条独立证据 |

## 输出契约

一份完整决策必须包含：

1. **结论**（四选一）
2. **决策置信度**及各阶段分解
3. **逐步中间结论**（三个阶段各自采纳/拒绝了什么）
4. **触发的判定**：阈值、观测值、触发理由、依据条款编号与原文
5. **被拒路径及理由**
6. **决策编号**（`DEC-` 开头），供后续审计与反向查询

第 6 项是审计的入口。任何结论被质疑时，凭决策编号可以还原完整推理链、
检查依据是否已过时，以及**反向查出还有哪些决策引用了某条已被废止的条款**——
最后一项是监管问询的高频问题：某条监管文件被废止时，
需要立刻找出所有引用了它的历史决策。
