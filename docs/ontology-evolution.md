# 低资源本体半自动构建

> 代码：`src/govfin/evolution/`
> 入口：`OntologyEvolutionPipeline.run()` ／ CLI `govfin evolve` ／ MCP `ontology_evolve`

## 一、问题：低资源域的本体从哪来

政务 + 金融这种领域，**没有现成的通用本体可以直接用**。金融侧有相对成熟的
行业标准（如监管指引条款里的风险维度划分），但政务侧各地接口各行其是：
同样是"企业被列入经营异常名录"这件事，有的接口写"经营异常名录"，有的写
"经营异常名录信息"，有的写"异常经营名录"。

手工建本体在低资源域行不通——领域专家没有时间把几十个统筹区的接口逐一看一遍，
而且下一次接口变更后还得重来。**因此本体必须能在运行中自己长出来，但不能自己乱长。**

这条要求的两个半边同样重要：
- **能长**：新概念反复出现时，系统要能识别出来并提出来；
- **不能乱长**：本体一旦被污染，后面所有类型约束、跨层边规则、路径搜索都会建立在
  错误的结构上，**且症状会出现在离病因很远的地方**。

## 二、整条管道只有两个出口

```
UNK 观测 ──► 储备池 ──► 聚类 ──► 符号对齐 ──► LLM 提案 ──► 一致性验证 ──► 提交
                                    │                        │              │
                                    │                        ├──► 拒绝 ─────┘
                                    └──► 别名学习             └──► 人工仲裁
```

**只有「拒绝」和「带着证据的版本递增」两个出口。没有"先加上去再说"这一档。**

### 1. UNK 储备池

类型未对齐到本体的元组一律进储备池，**不进图**。图上出现 `UNK-ENTITY` 节点会让后续
所有按类型写的约束（SHACL 校验、跨层边规则、路径搜索白名单）全部失效。

储备池因此不是垃圾桶，而是本体演化的**唯一输入**：每条 UNK 观测都记录来源文档、
定位与上下文，演化时要用。

### 2. 聚类

把同一概念的不同写法归拢。"经营异常名录" / "经营异常名录信息" / "异常经营名录"
应当聚成一簇，而不是变成三个类。

### 3. 符号对齐（先试已有的）

聚类之后**先试已有本体**，而不是直接新增。带后缀的写法（"社保缴纳记录信息"）剥掉
后缀就能命中已有的「社保缴纳记录」——这种情况学一条**别名**就够了，不需要新类。

**别名学习先于新增类**是一条重要次序：新增类是不可逆的（旧数据已经按旧类型存了），
而别名是可加的。能用别名解决就不动类结构。

### 4. 提案与置信度

提案由 `EditProposer` 产出。置信度的分配是这套机制的**核心安全阀**：

| 提案来源 | 置信度上限 | 后果 |
|---|---|---|
| 确定性启发式（无 LLM） | **0.45** | 低于自动采纳门槛，**必然**转人工仲裁 |
| LLM 提案 | 由模型给出 | 达到门槛且验证通过才自动生效 |

`AUTO_APPROVE_THRESHOLD = 0.6` 是刻意定的：

> **没有 LLM 参与时，不会有任何编辑自动落地。**

低资源域里"没把握就别改本体"应当是一条硬规则。启发式能识别出"这个词反复出现了"，
但它判断不了"这是不是一个领域概念"——把判断权交给人的成本，远低于让本体悄悄长歪的成本。

### 5. 一致性验证：克隆体上的试运行

验证环节用的**不是静态检查**，而是把候选编辑在**一份本体副本上真的执行一遍**，
再拿新本体去校验**现网已存在的图节点**。

这个区别是要害：

> 静态检查只能发现"公理自己矛盾"，发现不了"这条编辑会让图谱里 37 个已存在的
> 节点不再合法"。

新类挂到错误的父类下、新属性的 domain/range 与已有边冲突——这些问题的症状要到
**下一次路径搜索**时才出现，而且出现在离本体改动很远的地方。所以必须在上线前用
真实数据跑一遍。

### 6. 拒绝也要给理由

被拒的提案保留原因。实测中两条被拒的例子：

| 候选 | 拒绝原因 |
|---|---|
| `合计` | 候选形如噪声（长度不足或纯符号/数字），不足以构成领域概念 |
| `被列入` | 关系候选的上下文中无法同时定位 domain 与 range 两侧证据；**domain/range 猜错会污染路径搜索的路由**，因此不提案 |

第二条尤其能说明这套设计的态度：`被列入` 显然是个真实存在的关系，但因为无法
可靠地确定它连接哪两类实体，**宁可不要**。一个 domain/range 猜错的关系会让路径
搜索沿着错误的路由走出去，而这件事在图上看不出任何异常。

## 三、实测一轮

```
[3] 储备池：{'total': 7, 'unresolved': 7, 'resolved': 0,
             'unresolved_by_kind': {'entity': 5, 'relation': 2}, 'observations_pending': 17}
[4] 演化报告：
    version_before         0.1.0
    version_after          0.2.0
    clustered              5
    alias_learned          1
    auto_approved          ['社保缴纳记录信息']
    pending_arbitration    ['经营异常名录', '触发']
    replayable_tuples      3
    拒绝 2 条
[7] 本体版本链：[('0.1.0', 'system'), ('0.2.0', 'auto')]
```

- **5** 个 UNK 候选被聚类；
- **1** 条别名学习自动生效（`社保缴纳记录信息` → 已有类 `社保缴纳记录`）；
- **2** 条提案因置信度 0.45 < 门槛 0.60 转**人工仲裁**；
- **2** 条被**如实拒绝**并给出理由；
- 版本 `0.1.0 → 0.2.0`，版本链记录在演化元层上。

### 与行业规范标准对齐

种子本体（49 类 / 102 属性）里的规则层不是凭空造的：风险维度划分、条款编号体系、
阈值语义（"上限"/"下限"与比较方向）都对齐自监管指引条款的实际结构。演化新增的类
通过 `parent_class` **挂靠**到这套结构上（如 `经营异常名录` 挂靠 `工商登记`），
而不是另起一套平行体系。

## 四、可重放

`replayable_tuples` 记录的是：新本体生效后，**储备池里哪些元组现在可以进图了**。
演化不是"改完就算"，它会回头把当初因为认不出来而搁置的观测重新处理一遍。

这条闭环是"可进化"的实质：**本体的价值不在于它现在是什么样，而在于它能不能把
当初处理不了的数据变成处理得了的数据。**
