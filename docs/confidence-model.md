# 置信度模型：修正衰减

> 代码：`src/govfin/graph/confidence.py`
> 配置：`src/govfin/config.py` → `ConfidenceConfig`

## 一、为什么不能直接把边权乘起来

朴素做法是沿路径把边权连乘。这有两个致命缺陷，在信贷决策场景下都不能接受。

**缺陷一：乘积对跳数过度敏感。** 4 跳 0.95 的边相乘剩 0.81，4 跳 0.6 的边相乘只剩
0.13。同样是"4 跳"，两者的差距被放大到 6 倍以上——跳数本身而不是证据质量成了主导
因素。一条 4 跳链只要每跳都是铁证就已经被压到 0.81，而 2 跳链哪怕一半是推断也比它高。
这会让推理层系统性地偏爱短链，哪怕短链的证据更弱。

**缺陷二：弱边可以被强边掩盖。** 一条 0.99 的边乘一条 0.2 的边得 0.198，两条 0.45
的边相乘也是 0.203，几乎相同。但前者是"某一个环节完全不可信"，后者是"整体都一般"。
合规审核上必须区分这两者：前者意味着这条链上有一个断点，后者只意味着证据强度中等。
连乘把它们压成了同一个数字，而这个数字下游就是授信结论。

## 二、模型

把置信度拆成三个**互相独立**的因子，各管一件事，再合成：

```
conf = geo × hop × btn

geo = exp( -Σ λ_class(eᵢ) · (1 - wᵢ) )     证据质量衰减
hop = β^(n-1)                               跳数衰减
btn = γ + (1-γ) · min(wᵢ)                   瓶颈保护
```

| 因子 | 管什么 | 为什么这么设计 |
|---|---|---|
| `geo` | 每条边自身有多可信 | 用**指数衰减**而非连乘：弱边衰减得快，但它不会把整条链直接归零；多条一般边也不会互相放大惩罚 |
| `hop` | 链拉长带来的语义漂移 | `β=0.95` 意味着每多一跳折损 5%，是**温和**的惩罚。跳数该罚，但不该像连乘那样成为主导因素 |
| `btn` | 最弱那一环 | 用 `min(w)` 而不是乘积，**锚定**最弱环节而不是累积它。`γ=0.25` 是地板：一个环节再弱也不至于让整条链归零，判断权留给门槛 |

三者各自有界，乘出来仍在 `[0,1]`，且对"弱边"和"长链"**分别惩罚、互不掩盖**。

### λ 按证据类别取值

`λ` 惩罚的是"这条边离原始证据有多远"，越远的边被惩罚越重：

| 证据类别 | λ | 含义 |
|---|---|---|
| `direct` | 1.0 | 政务/金融系统的原始登记数据。来自登记机关的事实，系统不需要替它打折 |
| `derived` | 1.6 | 由规则条款推导出来的边。推导链条本身可能出错 |
| `llm` | 2.6 | LLM 抽取或推断产生的边。最远的一手，惩罚最重 |

这个取值的实质是：**"这家企业是否真实存在"这个问题的答案必须来自登记机关，不能来自
某个模型觉得它像存在。** 同样的边权，来自 LLM 的会被扣掉两倍多的分。

`llm` 类的边权还会用 **Beta 后验**随历史验证反馈校准（`llm_prior_alpha` /
`llm_prior_beta`），冷启动时回退到先验均值。

### 边的权重从哪来

`EdgeWeight.source` 字段记录了权重的出处，审计要能回答"这个 0.93 是怎么来的"：

| source | 含义 |
|---|---|
| `explicit` | 抽取时显式给出的置信度 |
| `rule_clarity` | 由所援引 Layer2 条款的"条款明确程度"决定——措辞越模糊，权重越低 |
| `feedback_calibrated` | 经历史验证反馈校准后的 Beta 后验 |
| `default` | 按边类型取 `DEFAULT_EDGE_CONFIDENCE` |

## 三、门槛：为什么每条约束的门槛不一样

路径的 `accept_threshold` **按约束分别设定**，而不是全局一个数。

这里的坑在于：如果全局门槛定得高，受罚的是"链长"；定得低，受罚的是"证据质量"——
无论定在哪，都是在用一个与业务无关的参数去决定业务结论。门槛表达的应当是
**"这一类结论需要多强的证据"**，而不同业务问题的答案本来就不一样。

| 约束 | 门槛 | 为什么 |
|---|---|---|
| 企业真实性核验 | **0.8** | 这条链只有 1~2 跳直接证据，分数天然在 0.85 以上。高门槛在这里的作用不是"卡住长链"，而是**当政务数据缺项、证据不完整时拒绝对企业真实性下结论** |
| 关联方风险传导扫描 | **0.5** | 四跳链上每跳都有一份政务原始记录。0.5 表达的是"关联推断可以进画像"——能提示风险，但不足以单独定案 |
| 授信决策链生成 | **0.35** | 三跳，每跳都能逐条回指条款原文与指标原文。门槛低**不是因为要求松**，而是因为分数里的多跳折损已经扣过了，再叠一个高门槛等于重复惩罚跳数 |

这三档门槛合起来表达的是一件事：**证据不足时应当拒绝对企业下结论，而不是给一个
看起来能用的低分结论。**

## 四、全局参数

| 环境变量 | 默认 | 含义 |
|---|---|---|
| `GOVFIN_HOP_DECAY` | `0.95` | `β`，每跳折损率 |
| `GOVFIN_BOTTLENECK` | `0.25` | `γ`，瓶颈地板 |
| `GOVFIN_DECISION_THRESHOLD` | `0.55` | 决策层的合成置信度门槛 |
| `GOVFIN_LLM_TEMPERATURE` | `0.0` | 抽取与提案必须确定性 |

> **改这些数等于改判定口径。** 它们不是性能参数，是业务口径参数——调高
> `GOVFIN_DECISION_THRESHOLD` 会让一部分原本"建议通过"的案子变成"审慎核定"。
> 改之前先看清楚它影响的是哪一档。

## 五、可解释性

每个路径的置信度都带**完整分解**，而不是一个孤零零的分数：

```json
{
  "score": 0.698196,
  "hop_count": 2,
  "geometry_factor": 0.794534,
  "hop_factor": 0.95,
  "bottleneck_factor": 0.925,
  "min_edge_weight": 0.9,
  "threshold": 0.5,
  "accepted": true,
  "reject_reason": null,
  "edge_weights": [ { "edge_id": "...", "weight": 0.93, "evidence_class": "direct", "source": "explicit" } ]
}
```

被拒的路径同样保留，并附 `reject_reason`。**"为什么没采信这条链"和"为什么采信了这条链"
是同等重要的审计问题**——只记录采纳结果，事后就无法回答"当初是不是漏看了什么"。
