# 桌面应用

## 一句话

双击 `GovFin.exe`，打开的是**软件**而不是网页。

```
GovFin.exe
  ├─ 决策工作台   七个独立按钮 + 过程可视化
  ├─ 服务状态     四块服务 + 拖拽导入材料
  └─ 部署与配置   项目目录 / API Key / 一键部署
```

## 怎么跑

```bash
python -X utf8 scripts/build_exe.py     # 产出 dist/GovFin.exe，并复制一份到项目根
```

开发时不用打包，直接跑源码：

```bash
python -X utf8 app/main.py              # 起原生窗口
python -X utf8 app/main_headless.py     # 只在 8124 起服务，用浏览器调界面
```

## 决策工作台

### 七个独立按钮，不是流水线

```
[🔍 真实性核验] [👥 社保缴纳] [⚖ 司法与处罚] [📊 财务解析]
[🕸 跨域推理]   [⚡ 决策合成] [📜 依据回执]
```

**每个都可以单独点**。只想看某家企业的行政处罚，不必等整套决策链跑完——
强制按顺序走完七步才能看一个数，是把系统的流程强加给用户的问题。

节点是 canvas 上的一层浮层（DOM 按钮），连线与粒子在画布上。
这样分工的理由：文字要能选中复制（DOM），而每帧都变的像素不该进 DOM（canvas）。

「依据回执」需要决策编号，没跑过「决策合成」时按钮是禁用态并说明原因——
而不是点了之后报一个"缺少参数"。

### 可视化在演什么

| 时机 | 效果 |
|---|---|
| 开始分析 | 背景网格缓缓流动 |
| 某步执行中 | 节点呼吸辉光，向下的连线自绘生长 |
| 某步完成 | 沿连线流动的粒子，节点冲击波涟漪 |
| 决策合成 | 置信度圆环从 0 转到目标值，数字同步滚动 |
| 阈值触发 | 阈值条转橙红 + 脉冲 + 画面轻微震动 |
| 依据回执 | 7 条证据链逐条滑入，各带来源角标 |

**为什么数字要滚**：直接显示 0.6209 的话，"算出来是 6 成 2"这件事没有分量。
从 0 走到 0.6209 的过程，本身就在传达"这是一个算出来的值"。

## 架构

```
GovFin.exe（PyInstaller 单文件，内嵌 Python）
  │
  ├─ 启动：解析项目目录 → 起本地 FastAPI（随机端口）→ 开原生窗口
  │
  └─ 本地服务
       ├─ 复用 console/app.py：/api/status /api/decision /api/kb /api/upload
       ├─ 新增 /api/step      单步执行（七个按钮的后端）
       ├─ 新增 /api/deploy/*  部署向导
       └─ 新增 /api/config/*  API Key 读写 / 连通性测试 / 注册到 Nexent
```

### 两个关键决定

**一、本地服务跑在宿主机，不在容器里。**

应用必须**在 Docker 完全没启动时也能打开**——否则"一键部署"这个功能自己就需要
先部署好才能用，成了循环依赖。同理，API Key 要写回**宿主机**的 `.env`，容器里写不了。

代价是容器主机名要换成本机端口。`console/app.py` 的环境变量全部走 `os.environ.get`，
所以只需在 import 之前设好（`app/server.py` 开头那段，顺序敏感，别往上挪）。

**二、首页路由是"替换"而不是"再注册一条"。**

FastAPI（Starlette）取**第一个**匹配的路由。控制台先注册了 `GET /`，
所以桌面端再注册一条同路径的**永远不会被调用**——服务一切正常、日志干净，
就是打开来是旧界面，排查起来会先怀疑缓存。

所以 `app/server.py` 里 `_override_root()` 直接改已有那条路由的 handler。
`tests/test_desktop_app.py` 有一条测试专门盯这个。

### exe 怎么找到项目目录

打包后 `__file__` 指向临时解包目录，不能用。解析顺序（`app/paths.py`）：

1. **exe 所在目录**（构建脚本会把 exe 复制一份到项目根，这是主路径）
2. **保存的路径**（`%APPDATA%\GovFin\config.json`）
3. **首次运行**：界面里选一个目录

找不到项目时应用**正常打开**——决策可视化照常可用，只是部署页给引导。
拦下来会让人以为软件坏了。

## 部署与配置

三段，自上而下就是该做的顺序：

```
① 项目目录    自动找到 / 手动指定
② API Key     填入 → 保存（写 .env）→ 测试连通性 → 注册到 Nexent
③ 一键部署    检查 Docker → 构建镜像 → 启动容器 → 接入 Nexent
```

### 写 `.env` 的三条自我约束

1. **逐行改写，不整体覆盖**。用户可能手写过注释、调过参数、加过我们不知道的键。
   整体覆盖会把那些悄悄抹掉，而他下次发现时已经想不起来自己写过什么。
2. **不改换行符**。Windows 上 `write_text` 默认把 `\n` 翻成 `\r\n`，
   一次"什么都没改"的保存会让整个文件在 git diff 里整篇变红，把真正的改动淹掉。
3. **空 key 表示"不修改"**。界面上不回填完整密钥，所以输入框本来就是空的——
   把空当成清空，会让用户一保存就把 key 弄丢。

Key 在接口里只回 `sk-********f085` 形式：前缀能看出是哪家的，末四位能对上是哪一把，
中间一律星号。

### 连通性测试是真调模型

不是校验 key 格式。一把过期的 key、一个写错的 base_url、一个没有余额的账号，
格式校验全都通过，然后在真正用的时候才炸——而那时报错的地方离原因很远。

所以这里真的发一次 `chat/completions`，并把 401/402/429 翻成人话
（"API Key 无效或已过期"/"账户余额不足"/"被限流"）。

### 部署进度用轮询而不是 SSE

`POST /api/deploy/start` 返回 `job_id`，前端每 700ms 拉一次增量日志。
WebView2 里 SSE 跨重启不稳定，而轮询在任何情况下都能自愈——刷新页面、开两个窗口，
都不会丢行或重复行。

## 测试

```bash
python -X utf8 -m pytest tests/test_desktop_app.py -q
```

17 条，盯的是**悄悄对不上**那类错误（都不报错，只是结果不对）：

- 步骤表引用的工具名与 `server.py` 实际注册的一致（工具名写错 → 界面显示"没有数据"）
- 传给工具的参数名是它接受的（多传/少传 → 这一步跑不出结果）
- `needs` 声明正确（错了按钮的禁用逻辑就错了）
- 首页路由真的被替换了（没替换 → 打开来是旧界面）
- 写 `.env` 保留注释、其它键、换行符
- 项目目录识别需要**两个**标记（只看 `pyproject.toml` 会认错别人的包目录）
- 损坏的配置文件不会让应用起不来

变异验证：`scripts/verify_mutations.py` 里这层有 6 处，**全部检出**。
