# 一键部署与控制台

## 一条命令

```bash
python -X utf8 scripts/one_click_deploy.py
```

跑完打开 **http://localhost:8090**。

脚本按顺序做四件事，每一步先检查当前状态，**已经做过的就跳过**——所以随时可以再跑一次：

| 步骤 | 做什么 | 已存在时 |
|---|---|---|
| 1 | 检查 Docker 守护进程 | — |
| 2 | 构建三个镜像 | 跳过（`--rebuild` 强制重建） |
| 3 | 启动容器并接入 `nexent_network` | 跳过，但**重新确认网络接入** |
| 4 | 在 Nexent 里开租户 / 注册 MCP / 导入 Skill / 配模型 / 建知识库 | 逐项跳过 |

登录 Nexent 用租户账号（**不是 `suadmin`**）：

```
govfin@nexent-demo.com  /  ***REDACTED***
```

## 为什么写成 Python 而不是 bash

目标机器是 Windows。bash 脚本要先有 Git Bash 或 WSL——那就等于要求用户为了"一键部署"
再装一样东西。Python 在需要跑这套系统的机器上必然存在（Nexent 的部署脚本也用它）。

## 为什么每步都要检查状态

一键部署最常见的失败不是"跑不起来"，而是**跑了两次，第二次建了一堆重复的东西**。
知识库塞满重复文档的后果不是报错，是检索结果被同一段话的不同副本挤满，真正相关的
那几条反而排不进 top_k。

所以这里的幂等不是"锦上添花"，是这条命令能被反复执行的前提。

## 控制台

`http://localhost:8090`，四个步骤按**你该做的顺序**排好：

```
检查服务  →  授信决策  →  知识库  →  Nexent 集成
```

**它解决的是什么问题。** 这套系统由四块组成——govfin 决策服务、本地向量化服务、
Nexent 平台、以及三者之间的注册关系。每一块单独看都还好，合起来就是：起服务要记
容器名，查状态要进数据库，注册要跑脚本。第一次接触的人会卡在"我该先做什么"。

两个刻意的设计：

1. **前端没有构建步骤**。单页 HTML，CSS 和 JS 都内联。有构建步骤就有"构建失败了
   所以页面打不开"这种故障，而这是运维工具——它打不开的时候，恰恰是你最需要它的
   时候。
2. **能自动做的都自动做**，不能自动做的明确写出卡在哪。用户不需要判断"网络通不通"，
   页面直接告诉他。

## 关于 DeepSeek 与知识库

**DeepSeek 不能做向量化。** 这不是配置问题，是能力缺口：它的 API 只提供对话端点，
`/v1/embeddings` 返回 **404**。而知识库的前提是"把文本变成向量"，两者不是一回事。

三条替代路线：

| 路线 | 代价 |
|---|---|
| 再注册一个云端 embedding 服务（SiliconFlow / DashScope / OpenAI） | 新账号、新 key，数据出网 |
| 用对话模型冒充 embedding | **做不到**。对话模型返回文本不是定长向量，硬凑出来的"向量"检索结果近似随机 |
| **本地跑一个小模型**（本项目采用） | 下一个约 100MB 的模型 |

选第三条还有一层考虑：政务场景里**数据不出网本身就是合规要求**，不是省钱。

实现见 `deploy/embedding/`：fastembed + `BAAI/bge-small-zh-v1.5`，走 ONNX Runtime
（不拉 torch，镜像小十倍），接口按 OpenAI 规范实现——Nexent 那边只要把 base_url
指过来就能用，不需要改任何代码。

验证：

```bash
curl -s http://localhost:8070/health
curl -s -X POST http://localhost:8070/v1/embeddings \
  -H "Content-Type: application/json" \
  -d '{"input":"社保缴纳异常"}'
```

返回 512 维向量。模型在**构建期**就下载好（走 hf-mirror.com，HuggingFace 国内直连不通），
否则第一次检索会卡住好几分钟，而用户看到的现象是"知识库建好了但搜不出东西"。

## 知识库

`scripts/sync_knowledge_base.py` 把领域文档灌进去，幂等可重跑。

进知识库的是**制度性与叙述性**材料（监管条款、征信报告、财报、判决书）。
结构化事实数据（社保记录、工商登记的 JSON）刻意**不放**——那些应该走图谱查询，
放进知识库只会让检索结果里混进字段片段，干扰对条款的召回。

验证检索确实有效（这是"建好了"和"能用"的分界）：

```
查询：社保 缴纳 异常 审慎核定 授信额度

分数 1.00  监管条款汇编  「…对关联方存在社保欠缴、行政处罚、重大涉诉等情形的，
                          应当将该情形纳入借款人经营稳定性评估，并相应下调授信评级」
分数 0.68  甲科技_2025年度财务报表
分数 0.47  甲科技_征信报告
分数 0.43  民事判决书_SF-2026-01-0233
```

语义检索把最相关的那条条款排在第一，而不是靠关键词命中。

## 容器清单

| 容器 | 端口 | 说明 |
|---|---|---|
| `govfin-agent` | 8930 / 8940 | MCP 工具 + A2A 协作 |
| `govfin-embedding` | 8070 | 本地向量化 |
| `govfin-console` | 8090 | 控制台界面 |

三者都用 `--restart unless-stopped`，机器重启后自动拉起。`govfin-agent` 和
`govfin-console` 需要接入 `nexent_network` 才能被 Nexent 访问。
