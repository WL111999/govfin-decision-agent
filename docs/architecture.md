# 架构

## 一、四层图模型

```
Layer 0  演化元层   本体版本 · 提案 · UNK 候选           （本体自己也在图上）
Layer 1  实体图     企业 · 工商登记 · 社保 · 处罚 · 自然人
Layer 2  规则图     监管条款 · 风险维度 · 阈值
Layer 3  运行时图   决策 · 证据束                        （决策痕迹）
```

### 为什么要分层，而不是一张大图

**规则必须独立成层。** "判不判"的依据是监管条款，而不是任何一条业务数据。把条款和
企业数据混在同一层里，路径搜索就无法区分"我走到了一个事实"和"我走到了一个规则"，
而这两者的可信度处理方式完全不同——前者按登记数据自带的可信度，后者按条款措辞的
明确程度。

**阈值必须是可以单独取到的节点。** 路径的终点刻意定成「阈值」而不是「监管规范」：
止步于条款只能证明"存在一条监管要求"，取到阈值才能回答"这条业务的判定边界是多少"。
前者的结论不可执行。因此**没有可解析阈值的条款不会进入结果集**，而是连同原因留在
`rejected_paths` 里等审计。

**演化元层放在 Layer 0 而不是"图外面"。** 本体版本、提案、UNK 候选都是图上的节点，
因此"这一版本体是从哪些提案长出来的"本身也是一次路径查询。把本体演化记录放在关系型
表里，就等于承认它不需要被推理——但它恰恰是最需要被追责的那部分。

## 二、跨层边规则

跨层边不是随手连的，写入时**强制校验**（`CROSS_LAYER_RULES`）：

| src → dst | 边类型 | 方向 | 含义 |
|---|---|---|---|
| 1 → 2 | 受约束于 | up | 实体所适用的监管条款 |
| 2 → 1 | 适用于 | down | 条款所约束的主体范围 |
| 2 → 1 | 对应指标 | down | 风险维度在主体上的指标实例化 |
| 3 → 2 | 决策依据条款 | up | 决策援引的条款 |
| 3 → 2 | 步骤引用条款 | up | 推理步骤援引的条款 |
| 3 → 1 | 决策涉及实体 | up | 决策激活的实体 |
| 3 → 1 | 步骤引用实体 | up | 推理步骤引用的实体 |
| 1 → 3 | 证据由决策采信 | down | 实体证据被某决策采信 |

不在表里的跨层组合写入即被拒。这条约束挡住的是一类很隐蔽的污染：**一次错误的跨层
连接会让后续所有路径搜索都从这条边走出去**，而图上看不出任何异常——它只是多了一条边。

## 三、数据流

```
   多模态文档                          五元组                   三层图
┌──────────────────┐          ┌────────────────────┐      ┌───────────────┐
│ JSON / CSV / TXT │  解析    │  entity_mention    │ 装载 │  实体归并      │
│ PDF              │ ───────► │  entity_type       │ ───► │  规则绑定      │
│ PNG/JPG (OCR×4)  │          │  attributes        │      │  完整性问题收集 │
└──────────────────┘          │  relation_*        │      └───────────────┘
                              │  evidence_*        │              │
                              └────────────────────┘              ▼
                                                          ┌───────────────┐
   决策 ◄──────── 约束路径搜索 ◄──────── 置信度传播 ◄───────│  跨层推理      │
    │                                                       └───────────────┘
    ▼
┌─────────────────────────────────────────────────────────┐
│ Layer3 运行时图：决策节点 + 证据束 + 逐步骤快照            │
│   └─► 依据漂移检测：决策后图上数据变了没有                  │
└─────────────────────────────────────────────────────────┘
```

### 五元组是认知层的统一表征

五类解析器（`text` / `table` / `json` / `pdf` / `image`）产出**同一种**结构，
因此装载层不需要知道一条事实是从 JSON 字段读来的还是从一页扫描件 OCR 出来的。
差别只保留在 `modality` 与 `evidence_class` 两个字段上，供置信度模型按证据远近打折。

**证据不可丢。** 每条边都必须携带 `evidence`（片段 + 模态 + 源文档 + 定位）。
决策溯源之所以能回指到"条款原文和实体数据快照"，靠的就是这一步没偷懒。定位粒度到
`record:4/缴纳状态` 这一级——不是"这份文件里有"，而是"这份文件的这一行"。

### UNK 不进图

任何类型未对齐到本体的元组一律送去**储备池**。图上出现 `UNK-ENTITY` 节点会让后续所有
类型约束、SHACL 校验、跨层边规则全部失效——它们都是按类型写的。储备池因此不是"垃圾桶"，
而是本体演化的**唯一输入**：

```
UNK 观测 ──► 聚类（同一概念的不同写法归拢）──► 别名学习（先试已有类）
                                              └─► 提案（新增类/属性）
                                                    └─► 一致性验证
                                                          ├─► 自动采纳
                                                          └─► 人工仲裁队列
```

## 四、关键接口

| 层 | 入口 | 作用 |
|---|---|---|
| 认知 | `parse(path)` / `parse_bytes(data, source=, suffix=)` | 多模态文档 → `ParsedDocument` |
| 认知 | `Extractor.extract(doc)` | `ParsedDocument` → `ExtractionResult`（五元组） |
| 图计算 | `GraphLoader.load(result)` | 五元组 → 图；产出 `LoadReport` |
| 图计算 | `GraphLoader.consolidate()` | 按强标识符做实体归并；产出 `ConsolidationReport` |
| 图计算 | `RuleBinder.bind()` | 建跨层边：约束边 / 指标边 / 阈值节点 |
| 推理 | `DomainTools.risk_decision(subject)` | 四阶段决策，写 Layer3 |
| 推理 | `DomainTools.evidence_bundle(decision_id=)` | 证据束 + 依据漂移检测 |
| 演化 | `OntologyEvolutionPipeline.run()` | 一轮演化闭环 |
| 服务 | `govfin.mcp.server` / `govfin.a2a.server` | MCP（10 工具）/ A2A（7 智能体） |

## 五、几个工程约束

**写代际缓存失效。** `GraphStore.write_generation()` 是单调递增的；**读操作绝不能推进它**。
邻接表是全量重建的，若一次读推进了代数，一次决策里的十几次路径搜索就变成十几次全表
重扫——小图上完全不可见（毫秒级），十万边上就是每次查询都超时。

**每线程连接 + WAL。** 但 `:memory:` 上只有单一共享连接（SQLite 的内存库无法跨连接
共享），这个不对称是脏读缺陷的根源，已在 `tests/chaos/test_concurrency.py` 中针对性
覆盖。

**事务必须显式收尾。** SQLite 由第一条 DML 隐式开启事务，只能通过 commit/rollback
结束。泄漏的事务会占用**数据库级 WAL 写锁**——一次被拒的重复写入，能让整个服务在此
之后写不进任何数据。

**图数据库必须持久化。** Layer3 是决策痕迹，是审计的依据。容器不挂卷，重建即丢失
全部"当初为什么这么判"。
